**Breaking changes found 2026-11-03 (not patch releases).** `cargo semver-checks`
flagged `nusselt_sphere` in heat-transfer (a third parameter was added). A
reading of the diff found `three_phase_power` in electrical now returns
`Option`, which the tool did not flag. Both need a 0.2.0 release under the
pre-1.0 rules. Their dependents must raise their version requirements when they
republish: `building-sys`, `examples`, `pcb`, `power-components`, `renewables`
(electrical); `building-sys`, `thermal-mgmt`, `unit-ops` (heat-transfer); and the
umbrella. `building-sys`, `examples` and `power-components` also call the changed
functions, so they need code updates, not just a version change.

**Row 12 resolved 2026-11-03.** The `Uniform` in the original note is
`rand_distr::Uniform`, an external type. The Phase 11A change in `d900916` moved the
call behind a finite-input check, and zero-width tolerances now skip the sampler.
Inverted bounds cannot occur. The tolerance changelog now says this.

**Verified 2026-11-03 against the published sources** (cached in the cargo
registry, compared with `scripts/pub_api_diff.py` and a whitespace-insensitive
source diff):

- `safety`, `cad`, `gdt`, `plot`, `timeseries`: only doc-test examples were added.
  No code change, so no bump.
- `mesh`: the binary STL length check was already in 0.1.0. No change, so no bump.
- `io`, `standards`: no source change, so no bump.
- Public-signature diff over every changed crate: only `electrical` and
  `heat-transfer` have breaking signature changes (listed above).

Behaviour-change warning for rows 1–9: several fixes change numbers that
callers may depend on (renewables PV, unit-ops stage count, pcb microstrip
impedance, electrical impedance guards, reliability Miner's rule). Each
CHANGELOG entry should say so under `### Fixed`, with the old and new value
where one is easy to state.

Row 15 check: a crate that is unchanged needs no bump. Do not republish for
formatting alone.

## 5. Decisions

Decided 2026-11-03:

1. **Patch vs minor for behaviour fixes: patch, unless the change breaks the
   API.** Behaviour-only fixes are 0.1.x patch bumps (or 0.1.x+1 for the
   already-published 0.1.1 crates). Each `### Fixed` entry must call out changed
   results. A breaking API change is a minor bump under the pre-1.0 rules in
   `docs/STABILITY.md`. Found 2026-11-03: `electrical` and `heat-transfer` need
   0.2.0 (see section 3).
2. **Umbrella `tpt-engineering`: publish.** Flag removed (see section 0). It
   goes last in the wave. Phase 11D's "fix the docs" alternative is dropped, so
   the README and `docs/guide` should be updated to show
   `tpt-engineering = { version = "0.1", features = [...] }` as the install
   path. **Done 2026-11-03** in `README.md` and `docs/guide/src/introduction.md`,
   marked as applying once the umbrella is published, with the individual-crate
   install shown until then.
3. **`tpt-math-*` alignment.** Checked 2026-11-03: the workspace pins
   `tpt-math-numeric`, `-linalg` and `-stats` to 0.2.0, and `cargo tree -d
   --workspace` shows no duplicate. The 0.1 copies come from the crates.io
   0.1.0 releases of the `tpt-eng-*` crates, not from the workspace. The
   Batch 10 republishes (already pinned to 0.2.0 in source) and the wave replace
   them. Remaining check after the wave: `cargo tree -d` on a fresh consumer
   project, to confirm one copy. `tpt-math-units` stays at 0.1.0 in the lock.
   Confirm that is intentional before the wave, since the workspace pins it
   separately.

Still open:

4. **Cosim, mcp, wasm, py.** Recommendation: keep all four unpublished. Reasons:
   `tpt-eng-py` is built into a wheel with maturin, which is the distribution
   path. `tpt-eng-wasm` is built into a browser or Node package from the repo.
   `tpt-eng-cosim` has a trait that is still changing. `tpt-eng-mcp` is a server
   binary that MCP clients run from source, and it depends on the unpublished
   `tpt-eng-sheet` until Batch 10 is live. Revisit cosim once its trait is
   stable.
5. **`cargo-semver-checks`.** Recommendation: run it on the wave as a gate, but
   not as the only check. Run 2026-11-03 on the 13 changed crates (0.51.0,
   baseline crates.io). It found one breaking change (`heat-transfer`). It did not
   find the breaking return-type change in `electrical`. For crates still at the
   published version, it compares against the same version and reports "assume
   minor", so its verdict is weaker there. Every changed crate also needs a
   manual review of the public API diff.

one every 10 minutes; see `RELEASE.md` §4). Only `provenance` and `sheet` are

but a 429 is still handled the same way: wait for the time in the error, then
re-run the same command.
