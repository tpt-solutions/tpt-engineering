# Changelog

All notable changes to the `tpt-engineering` workspace and its `tpt-eng-*`
crates are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Release record
- `tpt-eng-props`, `tpt-eng-structural`, `tpt-eng-standards`, `tpt-eng-gdt`,
  `tpt-eng-cad`, `tpt-eng-tolerance` and `tpt-eng-safety` are published at `0.1.1`
  on crates.io. The other 36 are at `0.1.0`. `docs/CRATE_VERSIONS.md` is the live record.

### Added
- `tpt-eng-sheet` (new, pending publication — Batch 10): declarative calculation
  sheets in TOML or JSON. Three calculations (`water-state`, `beam-udl`,
  `pid-step`), a committed JSON Schema, and `tpt-eng sheet run|schema` in the CLI.
  Each report lists its inputs, the formula for every step, references, and
  pass/fail with an overall status.
- `tpt-eng-report` 0.1.1: `Calculation` and `Step` build a calculation report
  (inputs, formula table, results with overall status, references, notes) from
  the existing section types, so the renderers are unchanged.
- `tpt-eng-cli`: `sheet run <file>` and `sheet schema` subcommands.
- `tpt-eng-py` (not published): a Jupyter tour notebook at `notebooks/tour.ipynb`.
- `tpt-eng-cosim` (not published): fixed-step co-simulation. A `Model` trait with
  named input and output ports, a `Simulation` runner that records every output,
  and three models: `Constant`, `FirstOrderLag` and `PidController`.
- `tpt-eng-mcp` (not published): a Model Context Protocol server over stdio.
  It offers `run_sheet`, which returns a sheet's report as Markdown, and
  `sheet_schema`. Sheet errors come back as tool errors, so a client can fix them.
  It also offers `tolerance_stackup`, `fuel_properties` and `moist_air_state`,
  which call the tolerance, fuel and air crates directly.
- `tpt-eng-props-mixture` 0.1.1: `pr_saturation_pressure_tagged`, `bubble_point_tagged`
  and `dew_point_tagged`. Each has a validity range below the critical temperature
  of the mixture's lowest-critical component. Existing signatures are unchanged.
- `tpt-eng-props-water`, `tpt-eng-props-air` and `tpt-eng-props-mixture` are at 0.1.1.
  Their `*_tagged` functions depend on `tpt-eng-provenance`, so they are republished
  after it.
- `tpt-eng-provenance` (new, pending publication — Batch 10): `Tagged<T>`,
  `Provenance`, `Validity`, `Source` and a `Warnings` bitset, for results that
  carry their source and validity range. `no_std`, no dependencies.
- `tpt-eng-props-water` and `tpt-eng-props-air`: `*_tagged` functions that return
  the same value as the untagged functions, plus an `OUT_OF_RANGE` warning when an
  input is outside the documented range. Existing signatures are unchanged.
- `tpt-eng-py` (not published): `tpt_eng.Tagged` results with `strict=True`, and
  air, fuels and structural bindings alongside water and controls.
- `tpt-eng-wasm` (not published): steam-table, section-property and PID demos
  for the browser, with a Node smoke test.
- 14 new domain crates (Phase 9, `docs/spec2.txt`): `tpt-eng-props-mixture`,
  `tpt-eng-electrical`, `tpt-eng-schedule`, `tpt-eng-biomech`,
  `tpt-eng-crystallography`, `tpt-eng-geotech`, `tpt-eng-heat-transfer`,
  `tpt-eng-vehicle-dynamics`, `tpt-eng-power-components`, `tpt-eng-pcb`,
  `tpt-eng-renewables`, `tpt-eng-building-sys`, `tpt-eng-thermal-mgmt`,
  `tpt-eng-unit-ops`. Published to crates.io at `0.1.0` in Batches 6-8 — see
  `docs/PUBLISH_TRACKING.md`.
- `tpt-eng-cli`: global `--json` output for `props water` and `props air`;
  `completions <shell>` prints a shell completion script.
- Runnable scenario binaries in `tpt-eng-examples`: `thermal_loop`, `solar_pv`,
  `mechanical_design`.
- Cookbook (`docs/guide`, mdbook) and `docs/VALIDATION.md` with the reference
  points each crate is checked against.
- Property-based tests (proptest) for three-phase power, stack-up intervals and
  saturation pressure.
- CI jobs: examples, doctest-check, each-feature build, coverage (lcov artifact),
  and mdbook build.
- Scenario binaries for distillation, construction schedule, building HVAC and
  PCB thermal design (`tpt-eng-examples`); all six scenarios are now runnable.
- `docs/CRATE_VERSIONS.md`, generated by `cargo xtask versions` from crates.io:
  the local version, workspace pin, registry version and release history of every
  publishable crate.
- `cargo xtask pin-check` (in `check`) and `cargo xtask link-check` (in `check`).
- Weekly scheduled CI run of the RUSTSEC audit; a Pages workflow for the cookbook
  (`book.yml`, needs Pages enabled).
- Issue templates, `CITATION.cff`, and `docs/STABILITY.md` (versioning policy).
- `tpt-engineering` gained a `full` feature bundle and docs.rs metadata.
- `tpt-eng crates [words]` and `tpt-eng recommend <task>`, backed by a catalog
  of every publishable crate (a unit test keeps it complete).
- `tpt-eng calc beam-file <beam.json>`: beam reactions, maximum moment and, with a
  section, utilisation, from a JSON description.
- Example outputs: each scenario writes a Markdown report and an SVG chart to
  `target/examples/`. Two new checks there are PASS/FAIL statuses from
  the report model.
- Reference file `crates/tpt-eng-structural/tests/reference/beams.csv` (six
  closed-form beam values with citations), checked by an integration test.
- Property tests for `heat-transfer`, `unit-ops` and `reliability` (nine properties).
- `cargo xtask package-check` (new CI job): every publishable crate packages.
- CI test job runs on Linux, Windows and macOS.

### Changed
- `tpt-eng-electrical::three_phase_power` now returns `Option` and takes a
  signed power factor (negative = leading); `tpt-eng-building-sys`,
  `tpt-eng-examples`, and `tpt-eng-power-components` updated to match.
- `tpt-eng-heat-transfer::nusselt_sphere` takes a `viscosity_ratio` argument
  (Whitaker `(μ/μ_s)^¼` term); `water_film_properties` returns `Option` and
  reports cp rather than enthalpy.
- `tpt-eng-props-mixture` and the `tpt-eng-props` umbrella are now no_std-clean
  (`libm` math, no allocation) and are in the no_std / wasm CI matrix.
- `tpt-eng-structural::Beam::try_add` added; `Beam::add` panics on loads outside
  the span.

### Documentation
- Crate-level examples added to all 42 library crates; `cargo xtask doctest-check`
  (run by `cargo xtask check`) fails if one is missing.
- `docs/CONVENTIONS.md` records the error strategy, unit convention and numeric
  precision rules.
- Planning and reference files moved to `docs/` (`spec.txt`, `spec2.txt`,
  `CRATE_AUDIT.md`, `PUBLISH_TRACKING.md`, `history/`).
- `tpt-engineering` umbrella docs now state it is not published.
- Workspace pins for `structural`, `standards`, `gdt`, `cad`, `tolerance` and
  `safety` moved from 0.1.0 to 0.1.1 to match their crate versions.
- `xtask` publish counts exclude members with `publish = false`.

### Fixed
- `tpt-eng-unit-ops::mccabe_thiele_stages`: the feed-line intersection used a
  wrong formula, so most reflux ratios with a non-zero feed q returned no
  solution. It now uses `x_i = (x_F + (q−1)·R_b) / (q − (q−1)·r_s)`.
- Broken relative links in four crate READMEs (`controls`, `network-matrix`,
  `props-air`/`-fuels`/`-water`, `structural`) now resolve.
- `tpt-eng-structural`: partial UDL moment double-counted the load for points
  beyond its end; zero-length UDLs produced NaN shear.
- `tpt-eng-unit-ops::gilliland_stages` now uses the Eduljee correlation and the
  `N = (N_min + Y)/(1 − Y)` inversion.
- `tpt-eng-pcb::microstrip_impedance` now uses Hammerstad–Jensen (continuous at
  `w/h = 1`); the previous closed form was ~30 % off there.
- `tpt-eng-props-air`: saturation pressure uses the over-ice form below 273.15 K;
  `dew_point` returns an error outside the search range instead of clamping.
- `tpt-eng-controls`: PID anti-windup integrated one extra step at the limit;
  `TransferFunction::new` rejects a zero leading denominator coefficient.
- `tpt-eng-renewables`: single-diode solve uses Newton iteration with a
  convergence check (was an unchecked fixed-point loop); `I_0` includes the T³
  term.
- `tpt-eng-reliability::miners_rule`: a block at or beyond failure now yields
  infinite damage instead of zero.
- `tpt-eng-tolerance::monte_carlo`: zero-tolerance dimensions no longer panic.
- `tpt-eng-electrical::skin_effect_ratio` no longer grows as `f` at high
  frequency.
- Guards for zero divisors and invalid domains in `tpt-eng-geotech`,
  `tpt-eng-power-components`, `tpt-eng-electrical` (capacitor, per-unit bases),
  and `tpt-eng-heat-transfer` (Re/Pr preconditions).
- `tpt-eng-electrical::impedance_parallel` treats a zero-impedance branch as a
  short (returns 0) instead of NaN.

## [0.1.0] - 2026-08-16

### Published (2026-08-15)
- All 29 `tpt-eng-*` crates from the initial workspace (13-crate Phase-0
  scope plus the structural/mechanical and geometry/CAD crates added
  post-Phase-4) released to crates.io at `0.1.0` — see `RELEASE.md` Batches
  1-5. No `v0.1.0` git tag has been cut yet.

### Added
- `tpt-eng-examples`: cross-crate integration scenario (`thermal_loop`)
  composing geo-topology → network-matrix → controls → timeseries → structural.
- `xtask doctest` and `xtask doc` commands.
- `tpt-eng-structural::Beam::max_bending_moment_with_resolution`.
- `SECURITY.md` vulnerability-reporting policy and supply-chain posture.
- `release.toml` (cargo-release) and root `justfile` onboarding targets.

### Changed
- `tpt-eng-props-air` now returns `Result` from `humidity_ratio`,
  `vapour_pressure_from_ratio`, `relative_humidity`, and `dew_point`, guarding
  against divide-by-zero and non-physical inputs (new `Error` enum).
- `tpt-eng-geo-asset::within_radius` now filters non-finite coordinates,
  matching `nearest`.
- `tpt-eng-network-matrix` no longer panics on dangling edge endpoints.
- CI: added `cargo-audit`, `wasm32-unknown-unknown`, and `docs`/`doctest`
  jobs; `cargo-deny` now denies unknown sources and yanked crates.
- `rustfmt.toml` no longer pins a conflicting `edition` (derived from
  `Cargo.toml`, workspace edition 2024).

Initial 13-crate release of applied engineering primitives:
`props-{water,air,fuels,props}`, `timeseries-{core,align,gap,timeseries}`,
`geo-{asset,topology}`, `network-matrix`, `controls`, `structural`.
